# Отчёт из сводной таблицы — макрос Excel (V3)

Файл для импорта: `dist/modОтчетИзСводнойV3.bas` (Windows-1251, CRLF).
Редактировать — `src/modОтчетИзСводнойV3.bas` (UTF-8), затем `python3 build.py`.

## Макросы

| Макрос | Что делает |
|---|---|
| `ОформитьОтчёт` | встать в сводную и запустить — строит отчёт на новом листе или в новой книге |
| `ОформитьОтчётБезВопросов` | то же без диалогов (для вызова из других макросов) |
| `ПалитраОтчёта` | сменить палитру готового отчёта на активном листе (спросит номер) |

Других макросов в списке Alt+F8 нет — всё остальное закрытое (`Private`).
Группировка строк кнопками +/- слева выключена: константа `ГРУППИРОВАТЬ`.

Палитры: 1 — тёмно-синий, 2 — серый (обе считаются от цвета шапки),
3 — A «старый формат» (персиковые итоги), 4 — B «стандартный шаблон»
(сине-серые итоги); цвета 3–4 — по PDF дизайна, уровни итогов 0–3
заданы явно, уровни глубже 3-го — светлее третьего.
Палитра нового отчёта — константа `ПАЛ_ПО_УМОЛЧ`.

После построения на листе нет ничего, кроме отчёта. Роль каждой
окрашиваемой ячейки (шапка, итог уровня 2, ключевая колонка…) хранится
в стиле-метке `Отчёт_*`: стиль ничего не форматирует, только помнит роль,
и по нему макрос палитры перекрашивает отчёт. Метки видны в галерее
«Стили ячеек» книги.

Названия элементов и мер берутся такими, как они показаны в сводной
(с учётом переименования), подпись общего итога — из самой сводной.

## Тесты ядра

Разбор структуры строк и шапки отделён от Excel (`'#ЯДРО-НАЧАЛО … '#ЯДРО-КОНЕЦ`)
и прогоняется в LibreOffice Basic (режим VBASupport) на сгенерированных сводных:

```
cd tests && python3 test_core.py      # 3240 кейсов строк + шапка
python3 test_core.py 100              # случайная выборка
python3 run_out.py                    # вывод отчёта и перекраска в эмуляции Excel
python3 manual.py                     # ручная проверка: 10 сводных «как на листе» -> отчёт текстом
python3 real.py книга.xlsm            # настоящая сводная из файла -> отчёт текстом
python3 deep.py                       # 10 уровней строк через весь путь до листа: порядок, цвета, жирность
python3 perf.py                       # время ядра на 6 и 21 тыс. строк
```

Перебираются: глубина 1–10; макет сжатый / структурный / табличный;
итоги сверху / снизу / без них; повтор подписей; общий итог; пустые строки
после групп; тёзки у разных родителей, подписи-числа и «итоговые» слова
в названиях; четыре режима того, что сообщает Excel (поле каждой ячейки;
поле, кроме ячеек итогов; только тип линии оси; ничего — текст и отступ).

`run_out.py` исполняет вывод на лист и смену палитры в эмуляции Excel
LibreOffice (VBASupport): порядок, итоги, отступы, жирность, форматы чисел,
заливки палитры 1 и перекраска в палитру B сверяются с ожидаемыми.
Стили-метки там подменены коллекцией: стили ячеек эмуляция не создаёт.
Снятие данных со сводной (PivotTable/PivotCell) вне Excel не исполнить.

`manual.py` — сводные, записанные руками так, как их размечает Excel
(структура с итогами вверху/внизу, табличная, сжатая); печатает исходную
сводную и готовый отчёт (жирность, отступы, заливки), чтобы проверить глазами.
Важно: при итогах вверху строка родителя — это линия промитога, подпись
без слова «Итог»; это разметка Excel, и на ней сломалась прошлая версия.

`real.py` берёт из сохранённой книги то, что макрос читает с листа сводной
(подписи строк с отступами, значения, шапку столбцов), и печатает отчёт рядом
с исходной сводной — в двух режимах: сводная сообщает типы ячеек и не
сообщает ничего; отчёты обязаны совпасть.

Объединение ячеек шапки строится планом ядра (`ПланШапки`) без пересечений:
Excel сливает пересекающиеся объединения в один блок и стирает подписи внутри
(эмуляция LibreOffice так не делает). `excel_merge.py` моделирует поведение
Excel, и тесты шапки и `real.py` проверяют, что ни одна подпись не стёрта.

Уровни шапки идут в том же порядке, что в сводной: если поле стоит выше
«Значений» — сверху элементы, под ними меры; если «Значения» первыми — меры
сверху. Общий итог и промежуточные итоги по столбцам — слева от своей группы.

Раскраска строк — по уровню (как в дизайне): общий итог, уровень 1, 2, 3…
своими цветами, нижний уровень сводной — детализация без заливки; строка
итога заливается целиком, вместе с «№». Отрицательные числа — без красного,
пустые значения — «–».

Шапка столбцов берётся с листа — ровно то, что видно в сводной (у модели
данных объектная модель отдаёт подписи элементов пустыми); из оси сводной
берётся только тип столбца (обычный / итог / промежуточный итог).
Строка фильтров — тоже с листа: подпись фильтра и значение рядом с ней.

Уровень строк определяется по месту на листе: столбец, а внутри столбца —
отступ. Сведения о полях от сводной (PivotCell) используются только когда
место неоднозначно: в одном столбце с одним отступом стоят разные поля
(сжатый макет с нулевым отступом). На модели данных (OLAP) сведения о полях
ненадёжны, поэтому основным признаком они не служат.

`tests/manual_result.txt` — последний результат `manual.py`: каждая сводная
проверена дважды — обычная и «модель данных» (поля не известны); отчёты
обязаны совпасть.
