# csv_report_builder

Папка CSV → одна Excel-книга в едином оформлении: каждый CSV — отдельный лист, плюс «Содержание»
со ссылками, «Справка по колонкам» и скрытый лист «Формулы». Движок — `report_builder.py` (консоль),
веб-приложение — `report_app.py` (тот же движок, без дополнительных зависимостей).

## Установка и запуск

```bash
pip install -r requirements.txt
```

### ReportMaker.exe — без установки Python

Готовый `ReportMaker.exe` собирается на GitHub при каждом обновлении `main` (сценарий
`.github/workflows/report-maker-exe.yml`: тесты → сборка → проверка exe: страница, анализ папки, сборка книги).
Скачать: вкладка **Actions** репозитория → «ReportMaker.exe» → последний зелёный запуск → **Artifacts** →
`ReportMaker-windows` (zip с exe; хранится 90 дней). Собрать у себя — `build_exe.bat` (нужен Python 3.10+),
результат в `dist\ReportMaker.exe`.

Двойной щелчок по exe — откроется консоль (не закрывать, пока работаете) и браузер. **Версия** видна в шапке
страницы рядом с названием и в первой строке консоли; если в браузере старая версия — закройте окна консоли
прежних запусков (они держат порт 8765) и запустите заново. Размер ~50–90 МБ, первый
запуск — несколько секунд (распаковка). Неподписанный exe может насторожить SmartScreen / антивирус:
«Подробнее → Выполнить в любом случае» или согласовать с ИТ.

### Отчёт-мейкер — веб-приложение (рекомендуется)

```bash
python report_app.py          # откроется браузер: http://127.0.0.1:8765
```

На Windows — двойной щелчок по `run_app.bat`. Работает локально и без интернета: сервер слушает только этот
компьютер, CSV никуда не отправляются, запросы с чужих сайтов отклоняются. Файлы в папке — любой структуры.

Сверху — папка («Выбрать…» / путь → «Анализировать»), снизу — «Собрать Excel». Между ними три вкладки:

| Вкладка | Что там |
|---|---|
| **Книга** | 5 настроек: заголовок, подзаголовок (отбор), период («9м» → «2026 9м»), рост — хорошо / плохо, палитра B / A |
| **Колонки** | Все колонки папки одной таблицей (одно имя — одна строка, видно, в скольких файлах): вид, подпись в шапке, подсветка «рост / снижение», пример, пометки. Виды: штуки / деньги / другое число / процент / Δ / Δ% / разрез / **уровень иерархии** / наименование / «из них» / не выводить |
| **Файлы** | Имя листа, описание, подзаголовок, строка «Итого», главная метрика (выделенная колонка и сортировка в иерархии), включить / пропустить; «просмотр» — лист справа, как в Excel, с текущими несохранёнными настройками |

**Группой:** поиск и фильтры (с пометками / метрики / разрезы / изменённые / добавленные Δ; группа отчётов
`19.*`, структура, с замечаниями) → «выбрать все видимые» → панель над таблицей: вид, подсветка, подпись —
«Применить» (40 колонок «Показатель N» — три щелчка); для файлов — шаблон имени листа («Отчёт {номер}»,
«{номер} {имя файла}»…), подзаголовок, «Итого», главная метрика, пропустить.

Всё, что не трогали, решает автоматика; изменённое помечено точкой и жирным, «Сбросить к авто» возвращает
автоматику. **Где действуют правки колонок** — список «Правки для» над таблицей: всех файлов (по умолчанию),
группы отчётов (`19.*`) или одного файла — тогда настройка пишется только этим файлам (`files.X.columns`),
поверх общей; «Сбросить к авто» в такой области возвращает файлам общую настройку.

**Шаблоны** — «Сохранить как шаблон» в верхней строке сохраняет все настройки (в `%APPDATA%\ReportMaker\templates`,
на Linux / Mac — `~/.report_maker/templates`); имена файлов обобщаются по дате выгрузки
(`rep_app_stac_1_1_202610290117.csv` → подходит к `rep_app_stac_1_1_<любая дата>.csv`, но не к отчёту 1.1 для
отчёта 1). Выбор шаблона в той же строке применяет его к открытой папке; при сборке настройки сохраняются в папку.

**Сборка** идёт в фоне: полоса прогресса и имя текущего файла. Сборка
сохраняет настройки в `report.yaml` (прежний — `report.yaml.bak`) — консоль читает тот же файл.

**Уровень иерархии** распознаётся по имени: «Уровень», «Ур», «Ур.», «Level», «Lvl», «Lev», «Depth», «Глубина»,
«Уровень иерархии», `level_1`, `lvl_x`; любую колонку с целыми числами можно отметить уровнем вручную
(вид «уровень иерархии»), а колонку подписей строк — «наименование».

### Консоль

```bash
python report_builder.py "D:\папка_с_csv"             # не больше 5 вопросов, сборка <папка>.xlsx рядом с папкой
python report_builder.py "D:\папка_с_csv" --explain   # как распознаны колонки, без сборки
python report_builder.py "D:\папка_с_csv" --no-ask    # без вопросов (по расписанию)
python report_builder.py "D:\папка" --out "D:\итог.xlsx" --config "D:\общий_конфиг.yaml"
```

На Windows — перетащить папку на `run_report.bat`. Вопросы (только если ответа ещё нет в `report.yaml`):
заголовок, подзаголовок, период, рост — хорошо или плохо, и пятый — колонки распознать автоматически
(по умолчанию) или проверить в консоли по типам отчётов. Имена листов назначаются сами: если у всех
нумерованных файлов одинаковая часть имени (`rep_app_stac_1_…`, `rep_app_stac_1_1_…`) — «Отчёт 1», «Отчёт 1.1».
Подробная настройка — в веб-приложении. `--ask` — спросить заново.

Без конфига и без вопросов всё определяется автоматически. Настройки — в `report.yaml` (пример —
`report.example.yaml`); веб-приложение и консоль читают и пишут один и тот же файл.

## Что делает

| Шаг | Что происходит |
|-----|----------------|
| Чтение | UTF-8 / UTF-16 / cp1251, разделитель `; , TAB \|` по согласованности строк (одна колонка с десятичной запятой `55723,69` — не два поля; спорный случай — замечание и ручная настройка `files: {"x.csv": {sep: ","}}`), полностью пустые строки пропускаются с замечанием, кавычки и переносы внутри поля, пустые строки пропускаются, строки с лишними полями → «Колонка N», повторяющиеся / пустые имена колонок → уникальные, `\N`/NULL → пусто, `? ` в заголовке → `Δ ` |
| Числа и даты | `1 234,5`, `12,5%`, `(150)` → −150, `1 000 ₽`, `1.5E+3`; inf — не число. Даты строго по формату колонки (`31.12.2025`, `2025-12-31`, с временем): `2026-02-01` — 1 февраля, `30.02.2026` — остаётся текстом с замечанием |
| Защита | Текст `=…` из CSV пишется текстом, не формулой; управляющие символы удаляются; текст > 32 767 символов обрезается; > 16 334 колонок — лишние отброшены. Битый файл (двоичный, пустой, только шапка) или сбой на одном листе не роняет книгу — файл в «Пропущенных» с причиной; все замечания — в колонке «Замечания» на листе «Содержание» |
| Роли колонок | метрика — ≥ 98% чисел, не код/ID/год/дата; вид по имени: Δ, Δ%, %/доля, сумма/руб, целые. Коды с ведущими нулями — текст |
| Итоги | Суммируются только штуки, деньги и их Δ; «другое число» (балл, коэффициент) и проценты — нет |
| Сверка и группировка | Иерархия: строка = сумма строк уровнем ниже (по умолчанию только деньги — штуки бывают уникальными, например пациенты; `table.check: all \| off`); расхождения — в «Замечаниях» и красным шрифтом в ячейке. Строки сгруппированы по уровням (кнопки +/− Excel, `table.outline: false` — без) |
| Иерархия | Колонка «Уровень». Порядок строк в CSV не важен (выгрузка может идти по уровням): родитель строки уровня N — строка уровня N−1 с теми же значениями разрезов (разрез относится к уровню, где впервые заполнен); «из них …» — сразу под строкой с теми же разрезами (того же уровня или уровнем выше); без совпадения — ближайшая строка выше с меньшим уровнем. Дети внутри групп — по главной метрике (по умолчанию сумма свежего года); `hierarchy_sort: off` — в порядке CSV |
| Годы | `X 2026` / `X 2025` → шапка в 2 строки; если Δ нет — добавляются Δ и Δ%; Δ% > 200% → «> 200%» |
| Значения | В ячейках только числа и заливки — без формул и условного форматирования. Формулы (Δ, Δ%, Итого с SUBTOTAL) и правила раскраски — текстом в примечаниях к заголовкам и на скрытом листе «Формулы»: вставить в первую ячейку диапазона и протянуть |
| Раскраска | Мягкая цветовая шкала по Δ / Δ%, отдельно в каждом блоке строк-деталей; рост — красный (`positive_is: good` — зелёный) |
| Цвета групп колонок | Шапка по виду метрики: штуки — #DCE8F3 (голубой), деньги — #DCEAD3 (шалфей), прочие числа и проценты — #D6ECEC (бирюзовый), Δ / Δ% — #FBF3E2 (песок), разрезы — #E8ECF0 |
| Оформление | Палитра B «стандартный шаблон»: заголовок #1B3A5C, подзаголовок #2D6A73, шапка разрезов #E8ECF0, уровни итогов сине-серые (#C9DCEC → #DCE8F3 → #EAF1F8 → #EEF4EA), ключевая колонка #ECEFF2, рамка #9AA5B1 / #D3D9DF, Δ — пары #F6DAD0 / #E1EEDC. Arial Narrow в таблицах, Arial в заголовках; ширина по содержимому, закреплённая шапка, печать по ширине, «Страница N из M». Палитра A — старый формат АПП |

## Настройки (`report.yaml`)

| Раздел | Что задаёт |
|--------|-----------|
| `book` | заголовок, подзаголовок, период («9м»), пояснения, вид листа «Формулы» (`hidden` / `visible` / `off`) |
| `files` | по маске имени файла: имя листа, описание, подзаголовок, `order` («1.4.1» — после 1.4), `skip`, `sep` (разделитель, если угадан неверно), свои `table` / `coloring` / `columns` |
| `columns` | по маске имени колонки: `label`, `role`, `kind`, `format`, `width`, `hidden`, `colorize`, `positive_is`, `description` |
| `style` | `palette: B \| A`, `colors` — переопределить любой цвет палитры, шрифт, размер, вид, масштаб, бумага |
| `table` | `compare`, `totals`, `sort` (порядок строк), `key` (главная метрика: выделенная колонка и сортировка в иерархии), `hierarchy_sort`, `formulas: values \| live` |
| `coloring` | `mode`, `positive_is`, `columns`, `pct_cap` |

Маски: точное имя, `*` / `?` или `re:регулярка`.

## Тесты

```bash
pip install -r requirements-dev.txt
pytest -q tests
```

54 теста: чтение (рваные строки, дубли колонок, UTF-16, кавычки с переносами, двоичные и пустые файлы), числа и
даты, защита от формул и управляющих символов, иерархия без наименования и с пропуском уровня, 40 файлов и
пустая папка, палитры, значения вместо формул, вопросы (группировка по структурам, сохранение ответов, повторный
запуск без вопросов, ошибки ввода, `!`), разнородная папка (вопросы только по сомнительным структурам),
широкий файл (сводка, `*`), подпись «Итого», когда первая колонка — метрика, 30 случайных файлов 1–120 колонок,
иерархия из выгрузки «по уровням», не больше 5 вопросов в консоли, строки Arrow (pyarrow); веб-приложение
(`tests/test_app.py`): колонки папки одной таблицей, правка группой (60 колонок), сброс к автоматике, пропуск
файла, подзаголовок файла, уровень, отмеченный вручную, синонимы уровня, предпросмотр без сохранения, повторный
анализ видит сохранённое, HTTP-сервер и защита от запросов с чужих сайтов.

Дополнительно проверено фаззингом: 1 800 случайных файлов (1–250 колонок, текст / коды / даты / деньги /
проценты / «почти числа» / пустые колонки, разные кодировки и разделители, часть — без метрик) — для каждого
сверены с исходным CSV число строк и суммы всех числовых колонок: расхождений нет.

## Ограничения

- Иерархия восстанавливается по колонкам разрезов: если у строки разрезы пустые или не совпадают с родителем
  (опечатка в названии группы), она встаёт под ближайшую строку выше с меньшим уровнем.
- `1,234` без точки читается как 1.234 (десятичная запятая), не как тысяча.
- Шапка максимум в 2 строки; без `columns.label` в шапке технические имена (`MO_NAME`).
- Заливка рассчитана с приглушением средних значений — стандартная шкала Excel по записанному правилу даст их ярче.
- Скорость и память (замер, 200 тыс. строк × 18 колонок): ~80 с; память — ~0,4 ГБ (потоковая запись: строки
  сразу уходят в файл; включается сама, если CSV в сумме больше 2 МБ; `book.stream: true / false`). Без потоковой
  записи было бы ~1,8 ГБ. Книга в обоих режимах одинаковая (проверено сравнением ячейка в ячейку). Для листов
  больше 1,5 млн ячеек — предупреждение о времени: такие данные лучше агрегировать.
- Больше ~1 млн строк — обрезается с предупреждением (лимит листа Excel).
